# AGV 小车技术文档

## 1. 项目概述

本项目是一个基于 `STM32F103C8T6` 的 AGV 小车控制系统，使用 STM32CubeMX 生成基础工程，应用层在 `Core/Src` 中实现。系统围绕“刷卡启动任务、循迹行驶、超声避障、到站取货、终点停车”这一完整流程组织，适合课程设计、比赛演示和后续功能扩展。

当前固件已经集成以下能力：

- RFID 刷卡识别任务
- 5 路红外循迹
- HC-SR04 超声波测距
- TB6612 双路直流电机驱动
- 双路编码器测速
- 舵机执行取放动作
- OLED 状态显示
- USART3 串口调试输出

## 2. 功能流程

系统主流程如下：

1. 上电后初始化 GPIO、定时器、串口和应用层模块。
2. OLED 显示等待刷卡提示，车辆处于待机状态。
3. 刷到有效 RFID 卡后进入任务准备状态。
4. 延时 2 秒后开始循迹。
5. 根据 RFID 卡类型决定中途停车站点。
6. 到达目标站后停车，舵机执行取货动作。
7. 继续循迹前往最终停止线。
8. 行驶过程中若检测到障碍物，则进入避障状态机。
9. 到达终点后停车，任务复位，回到待刷卡状态。

## 3. 软件架构

### 3.1 分层结构

- `main.c`
  负责 HAL、时钟、基础外设初始化，并在 `while(1)` 中循环调用 `AppVehicle_Task()`。
- `app_vehicle.c`
  整车应用层核心，负责状态机调度和各功能模块协同。
- `app_line.c`
  读取 5 路红外传感器状态，并计算循迹偏差。
- `app_motor.c`
  电机驱动封装，支持开环 PWM 和基于编码器反馈的闭环 PI 控制。
- `app_encoder.c`
  通过 EXTI 中断统计左右轮编码器计数。
- `app_ultrasonic.c`
  驱动 HC-SR04，完成触发、回波测量、超时处理和距离换算。
- `app_rfid.c`
  封装 RC522 读卡逻辑，识别业务卡 A/B。
- `app_servo.c`
  基于 TIM4 CH4 输出舵机 PWM。
- `app_oled_ui.c`
  负责 OLED 文本显示与状态提示。

### 3.2 主循环结构

主循环非常简洁：

```c
while (1)
{
    AppVehicle_Task();
}
```

这意味着所有上层行为都集中在 `AppVehicle_Task()` 内部统一调度，便于维护和扩展。

## 4. 状态机设计

整车状态定义在 `Core/Src/app_vehicle.c`：

- `VEHICLE_WAIT_CARD`
  待刷卡
- `VEHICLE_CARD_STANDBY`
  刷卡后等待发车
- `VEHICLE_LINE_FOLLOW`
  正常循迹
- `VEHICLE_STOPPING`
  到站停车/取货/终点停车
- `VEHICLE_AVOID_LEFT`
  避障第一阶段，左转绕障
- `VEHICLE_AVOID_FORWARD`
  避障第二阶段，前进脱离障碍
- `VEHICLE_AVOID_RIGHT_ALIGN`
  避障第三阶段，右转修正姿态
- `VEHICLE_AVOID_RETURN_FORWARD`
  避障第四阶段，前进回归线路区域
- `VEHICLE_AVOID_RIGHT`
  避障第五阶段，右转搜索主线

### 4.1 RFID 任务规则

- 卡 `A` 对应第 `1` 条目标停止线。
- 卡 `B` 对应第 `2` 条目标停止线。
- 完成取货后，统一继续前往第 `3` 条停止线作为最终终点。

### 4.2 黑线判定逻辑

系统通过 5 路红外统一命中、连续确认帧数达标后，认为通过了一条完整黑线，并递增 `s_crossed_line_count`。

当前关键参数：

- 黑线确认帧数：`LINE_BLACK_CONFIRM_FRAMES = 3`
- 目标终点线：`s_final_stop_line = 3`

## 5. 循迹控制策略

循迹模块位于 `Core/Src/app_line.c` 与 `Core/Src/app_vehicle.c`。

### 5.1 传感器输入

5 路红外输入连接在：

- `PA1` -> `IR1`
- `PA2` -> `IR2`
- `PA3` -> `IR3`
- `PA4` -> `IR4`
- `PA5` -> `IR5`

代码中配置为上拉输入，且默认采用低电平检测到黑线：

- `APP_LINE_IR_ACTIVE_LOW = 1U`

### 5.2 误差计算

红外权重定义如下：

- `IR1 = -4`
- `IR2 = -1`
- `IR3 = 0`
- `IR4 = 1`
- `IR5 = 4`

通过加权平均得到横向偏差 `error_x10`，再乘以比例系数形成左右轮差速控制量。

### 5.3 当前循迹参数

- 基础占空比：`LINE_BASE_DUTY_PM = 160`
- 最小占空比：`LINE_MIN_DUTY_PM = 50`
- 最大占空比：`LINE_MAX_DUTY_PM = 650`
- PID 调整周期：`LINE_PID_INTERVAL_MS = 10`
- 比例系数：`LINE_KP_PM_PER_ERR10 = 8`

当前实现本质上是比例控制，尚未引入积分和微分项。

## 6. 避障策略

避障由超声波测距触发，核心阈值定义在 `Core/Src/app_vehicle.c`：

- 障碍判定距离：`OBSTACLE_THRESHOLD_CM = 20`

当车辆在循迹或避障运动状态下，若检测到前方距离小于等于 20 cm，则进入避障流程。

当前避障动作顺序如下：

1. 左转绕开障碍物
2. 前进一段距离
3. 右转对齐
4. 再前进一段距离
5. 右转搜索主线
6. 检测到边缘线后重新接入循迹

关键时间参数：

- 左转：`850 ms`
- 前进：`180 ms`
- 右转对齐：`760 ms`
- 回归前进：`1400 ms`
- 右转搜索超时：`1600 ms`

## 7. 电机与编码器控制

### 7.1 电机驱动

电机驱动芯片为 `TB6612`，PWM 由 `TIM1` 输出：

- `PA8` -> `TIM1_CH1`
- `PA9` -> `TIM1_CH2`

方向控制引脚：

- `PB6` -> `AIN1`
- `PB7` -> `AIN2`
- `PB4` -> `BIN1`
- `PB3` -> `BIN2`
- `PB5` -> `STBY`

### 7.2 开环/闭环模式

`app_motor.c` 同时支持两种模式：

- 开环模式：直接输出 PWM 占空比
- 闭环模式：根据编码器反馈进行 PI 调节

当前固件默认配置：

- `ENABLE_MOTOR_CLOSED_LOOP = 0U`

即默认运行在开环模式，便于先恢复基础循迹能力。

### 7.3 编码器接口

编码器接线如下：

- 左轮 `E1A` -> `PA12`
- 左轮 `E1B` -> `PA15`
- 右轮 `E2A` -> `PA10`
- 右轮 `E2B` -> `PA11`

实现方式：

- A 相使用双边沿 EXTI 中断计数
- B 相同步采样判断方向

方向修正参数：

- `ENC_LEFT_DIR_SIGN = -1`
- `ENC_RIGHT_DIR_SIGN = 1`

如果某一路方向不对，可优先交换 A/B 相接线，或者调整上述符号。

### 7.4 电机闭环参数

当前闭环 PI 参数如下：

- 控制周期：`20 ms`
- 目标速度上限：`900 pps`
- 最小有效占空比：`40`
- 最大占空比：`500`
- `KP = 3/8`
- `KI = 1/8`

另外还实现了“有目标速度但编码器长期无反馈”的保护逻辑，防止堵转。

## 8. 超声波模块

超声波模块使用 `HC-SR04`：

- `PB0` -> `TRIG`
- `PB1` -> `ECHO`

实现特点：

- `TIM2` 配置为 1 MHz 计数，1 个计数对应 1 us
- 采用 `EXTI1` 捕获回波上升沿和下降沿
- 通过脉宽除以 `58` 换算为厘米
- 支持超时处理和无效回波过滤

当前参数：

- 测量超时：`35 ms`
- 有效脉宽范围：`100 us ~ 25000 us`
- 静止测量周期：`100 ms`
- 运动测量周期：`140 ms`
- 距离突变容忍阈值：`25 cm`

串口调试默认开启：

- `ENABLE_ULTRASONIC_UART_REPORT = 1U`

## 9. RFID 模块

RFID 使用 `RC522`，采用软件 SPI：

- `PB12` -> `MISO`
- `PB13` -> `MOSI`
- `PB14` -> `SCK`
- `PB15` -> `SDA/SS`

当前业务卡 UID 写死在 `Core/Src/app_rfid.c`：

- 卡 A：`16 15 12 07`
- 卡 B：`1E F1 2B 07`

轮询周期：

- `APP_RFID_POLL_INTERVAL_MS = 100`

并带有去重逻辑，避免同一张卡持续贴近时反复触发任务。

## 10. 舵机与 OLED

### 10.1 舵机

舵机输出：

- `PB9` -> `TIM4_CH4`

定时器配置：

- `TIM4` 计数频率 1 MHz
- 周期 20 ms

角度转换范围：

- `500 us` 对应接近 `0°`
- `2500 us` 对应接近 `180°`

当前任务相关角度：

- 运行角度：`55°`
- 取货角度：`90°`

### 10.2 OLED

OLED 采用软件 I2C：

- `PA6` -> `OLED_SCL`
- `PA7` -> `OLED_SDA`

OLED 主要显示：

- 待刷卡提示
- 当前目标站点
- 最近一次 RFID UID
- 超声距离
- 避障或取货动作状态

## 11. 串口调试

调试串口使用 `USART3`：

- `PB10` -> `TX`
- `PB11` -> `RX`
- 波特率：`115200`
- 格式：`8N1`

当前常见输出内容包括：

- 超声测距结果，如 `US:020cm`
- 超声无回波，如 `US:NONE`
- 编码器计数，如 `ENC L:123 R:118`
- RFID UID 文本

## 12. 外设与时钟配置

系统时钟配置：

- 外部高速晶振 `HSE`
- PLL 倍频到 `72 MHz`
- `AHB = 72 MHz`
- `APB1 = 36 MHz`
- `APB2 = 72 MHz`

定时器用途：

- `TIM1`：电机 PWM
- `TIM2`：超声波微秒计时
- `TIM4`：舵机 PWM

## 14. 调试与修改建议

### 14.1 首次联调建议

建议按以下顺序联调：

1. 先确认 `OLED` 和 `USART3` 正常输出。
2. 再检查 5 路红外是否能稳定读到黑线。
3. 检查超声波串口输出是否稳定。
4. 单独测试电机正反转和左右轮方向。
5. 查看编码器计数是否随轮子转动变化。
6. 最后再联调整车状态机。

### 14.2 需要特别注意的点

- 代码当前启用了 `MOTOR_SWAP_PWM_OUTPUTS = 1U`，表示左右 PWM 输出做了交换适配。
- 如果左右轮实际接线与代码假设不一致，需要修改 `Core/Src/app_motor.c`。
- `PA15` 被用作编码器输入，因此工程已关闭 JTAG，仅保留 SWD。
- 当前默认关闭电机闭环，若需要启用，请将 `ENABLE_MOTOR_CLOSED_LOOP` 改为 `1U`。
- 红外模块默认按“低电平检测到黑线”处理，若你的模块逻辑相反，需要修改 `APP_LINE_IR_ACTIVE_LOW`。

## 15. 文档结论

本项目已经形成较完整的 AGV 控制闭环：

- 输入层：RFID、红外、超声、编码器
- 控制层：整车状态机、循迹控制、避障逻辑、电机驱动
- 输出层：直流电机、舵机、OLED、串口

从代码结构看，模块职责划分清晰，适合继续扩展以下方向：

- 启用并整定电机闭环控制
- 增加更多 RFID 站点任务
- 将避障策略改为更稳定的路径规划方式
- 增加电池电压采样和低电压保护
- 引入 RTOS 或任务调度框架
